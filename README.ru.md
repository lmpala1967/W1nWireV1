# W1nWire

Свой VPN, собранный с нуля: собственный протокол шифрования, приложение для
Windows с нормальным интерфейсом и сервер, который можно поднять бесплатно.
Написан на Go, лицензия MIT. Без подписок, без аккаунтов, без телеметрии.
Исходники полные, правьте как хотите.

## Быстрый старт

### 1. Сервер (минут 5, бесплатно)

Нужна виртуалка с Ubuntu 24.04. Проще всего взять **Oracle Cloud Always Free**,
пошаговая инструкция лежит в [docs/ORACLE.md](docs/ORACLE.md). Дальше на самой
машине выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/w1nchi/w1nwire/main/deploy/install.sh | sudo bash
```

Скрипт сам скачает нужный бинарник, создаст ключи, добавит systemd-юнит,
включит форвардинг и NAT, откроет UDP-порт и в конце покажет примерно такое:

```
============================================================
 W1nWire server is running
 Address: 203.0.113.7:51820
 Invite code (copy the whole line into the W1nWire app):
 ww1.eyJ2IjoxLCJuIjoiZGVza3RvcCIsImgiOiIyMDMuMC4xMTMuNzo1MTgyMCIs...
============================================================
```

Код приглашения нужно хранить в секрете. Внутри него адрес сервера, публичный
ключ сервера и приватный ключ одного клиента, так что обращайтесь с ним как с
паролем.

Подойдёт любой VPS с Ubuntu 22.04/24.04 или Debian 12, к конкретному
провайдеру скрипт не привязан. Перед тем как выставлять сервер в интернет,
прочитайте [deploy/README.md](deploy/README.md) и [docs/SERVER.md](docs/SERVER.md).

### 2. Клиент для Windows

Скачайте `w1nwire-desktop.exe` на странице
[релизов](https://github.com/w1nchi/w1nwire/releases) или соберите сами
(`make desktop`). Запустите, нажмите **«Добавить сервер» → «Импорт кода»**,
вставьте код приглашения и нажмите **«Подключить»**.

Есть два режима:

* **Туннель.** Один раз попросит права администратора: приложению нужно
  создать адаптер Wintun и поменять таблицу маршрутов. После этого весь трафик
  компьютера идёт через сервер.
* **Прокси.** Права не нужны. Приложение поднимает SOCKS5 на `127.0.0.1:1080`
  и, если хотите, само переключает системный прокси Windows.

На главном экране видно адрес, который вам выдали в туннеле, время работы,
скорость и живой график. Во вкладке **«Журнал»** можно посмотреть, чем сейчас
занят клиент.

### 3. iPhone (тоже бесплатно)

На сервере запустите установщик ещё раз с флагом `--ios`. Если сервер уже
настроен, подойдёт `sudo ./install.sh --ios`. Он поднимет WireGuard на
UDP 51821 и покажет QR-код. Поставьте бесплатное приложение **WireGuard** из
App Store, отсканируйте код и включите туннель. Подробности в
[docs/IOS.md](docs/IOS.md).

На iPhone работает WireGuard, а не протокол W1nWire. Нативный VPN на iOS
требует Network Extension, а для него нужен платный аккаунт Apple Developer
(99 долларов в год). Бесплатный WireGuard справляется с задачей не хуже, а
сервер понимает оба протокола.

## Режим прокси

Модуль `internal/socks5` принимает CONNECT на `127.0.0.1:1080`. Имя хоста
передаётся внутри туннеля (`FrameOpen`) и разрешается на сервере, поэтому
клиент сам DNS-запросов не делает и ничего не утекает.

Переключатель **«Системный прокси»** меняет настройки в
`HKCU\...\Internet Settings`, а при отключении возвращает всё как было, вместе
с PAC-скриптом, если он был. Chrome, Edge и другие программы, которые читают
настройки WinINET, подхватывают прокси сразу. Firefox и Telegram придётся
направить на `127.0.0.1:1080` вручную.

## Сборка из исходников

Нужен Go 1.26 или новее. Для иконки больше ничего ставить не надо, генератор
ресурсов тоже написан на Go.

```bash
# приложение для Windows (запускать из Windows)
pwsh -File scripts/build-windows.ps1 -Version 2.0.0

# или через GNU make на любой системе
make desktop          # dist/w1nwire-desktop.exe, кросс-компиляция
make dist             # приложение, серверы под Linux и установщик
make test             # тесты
```

Скрипт `scripts/build-windows.ps1` гоняет тесты, делает иконку, манифест и
информацию о версии через `go-winres`, собирает GUI-приложение, компилирует
сервер под amd64 и arm64 и упаковывает всё в zip вместе с `SHA256SUMS.txt`.

```
cmd/w1nwire-client/     консольный клиент (прокси или туннель на Linux)
internal/app/           профили, настройки, движок, самотест, системный прокси
internal/ui/            встроенный интерфейс на одной странице и локальный JSON API
internal/client/        состояние клиента, режимы туннеля и прокси
internal/server/        UDP-сервер, маршрутизация пиров, пересылка потоков
internal/protocol/      рукопожатие, сессия, сообщения, окно повторов
internal/crypto/        X25519, HKDF-SHA256, ChaCha20-Poly1305
internal/tunnel/        кадры, менеджеры потоков на клиенте и сервере
internal/tun/           TUN-устройства: Linux, Wintun, loopback
internal/socks5/        локальный SOCKS5-сервер
internal/winproxy/      настройки прокси WinINET с точным восстановлением
internal/winutil/       права, автозапуск, один экземпляр
internal/invite/        формат кода приглашения
deploy/                 установщик, systemd-юниты, cloud-init, Terraform
monitoring/             Prometheus, дашборд Grafana, алерты
docs/                   протокол, архитектура, модель угроз, руководства
packaging/icon/         генератор иконки и готовая иконка
scripts/                скрипты сборки
```

## Безопасность

* Сервер расшифровывает туннель, так что тот, кто им владеет, видит, куда вы
  ходите, а в режиме прокси ещё и содержимое соединений. Поэтому держите
  собственный сервер.
* Код приглашения это ключ доступа. Если он утёк, выполните
  `w1nwire-server peer remove`, а затем `peer add`.
* Протокол не маскируется. Система глубокой инспекции трафика (DPI), которая
  знает заголовок, может его распознать и заблокировать. Ни паддинга, ни защиты
  от анализа по времени пакетов нет.
* Приложение для Windows не подписано, поэтому при первом запуске SmartScreen
  будет ругаться. В релизе есть `SHA256SUMS.txt`, по нему можно сверить файл.
* Полный разбор угроз в [docs/THREAT-MODEL.md](docs/THREAT-MODEL.md).

## Ограничения

* Внутри туннеля только IPv4. IPv6 не пропускается, а блокируется.
* SOCKS5-прокси умеет только TCP (`CONNECT`), UDP отклоняется.
* Режим туннеля работает на Windows (Wintun) и Linux (TUN). На macOS доступен
  только прокси.
* Собственного приложения для iOS нет, iPhone подключается через
  WireGuard-эндпоинт того же сервера.
* Kill switch нет. Если клиент упал, маршруты убираются, и трафик идёт
  напрямую через обычное подключение.
* Сервер видит открытый текст, а клиент доверяет тому серверу, который указан
  в профиле.
